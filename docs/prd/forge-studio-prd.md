## 1. 배경 및 목적

### 문제 정의

AI 코딩 어시스턴트(Claude Code, Cursor, Copilot 등)가 보편화되었지만, **"AI를 어떻게 잘 쓰는가"**에 대한 정답은 없다. 개발자마다 자신만의 하네스(harness) - 에이전트 구성, 워크플로우, 원칙, 커맨드 - 를 만들어야 하지만:

1. **설정이 분산되어 있다**: CLAUDE.md, .claude/agents, commands, skills, hooks, MCP 서버가 모두 별개의 텍스트 파일
2. **시각화가 없다**: 워크플로우 상태, 에이전트 관계, 품질 메트릭을 한눈에 볼 수 없다
3. **기술 스택마다 처음부터 구축**: Flutter용, Next.js용, Python용을 매번 새로 만든다
4. **기획 → 구현의 연결이 약하다**: 기획문서 import, 스펙 생성, 구현 추적이 수작업
5. **학습이 축적되지 않는다**: lessons-learned가 있어도 프로젝트 간 공유가 안 된다

### 비전

> **"나만의 AI 개발 하네스를 시각적으로 설계하고, 어떤 기술 스택이든 적용할 수 있는 데스크톱 앱"**

Forge Studio는 Claude Code CLI 위에 앉아서:
- 워크플로우를 **시각적으로 설계**하고
- 에이전트/커맨드/스킬을 **GUI로 조합**하고
- 기획문서부터 배포까지 **전 과정을 추적**하고
- MCP 서버를 **직접 만들고 관리**하며
- 축적된 지식을 **프로젝트 간 재사용**한다

### 핵심 가치

| 가치 | 설명 |
|------|------|
| Visual Harness Engineering | 텍스트 파일이 아닌 시각적 인터페이스로 AI 하네스 설계 |
| Stack Agnostic | Flutter, Next.js, Python, Go 등 어떤 스택이든 적용 |
| Document-Driven | 기획 → 설계 → 구현 → 검수의 문서 주도 개발 |
| Self-Improving | 실수 패턴 추적, 크로스 프로젝트 학습, 자동 규칙 진화 |
| Open Architecture | MCP 서버 직접 제작, 커뮤니티 템플릿 공유 |

## 2. 타겟 사용자

### Primary: 하네스 빌더 (개인 개발자)

| 속성 | 설명 |
|------|------|
| 프로필 | Claude Code/Cursor를 적극 활용하는 개발자 |
| Pain Point | 매 프로젝트마다 CLAUDE.md, 에이전트, 커맨드를 처음부터 텍스트로 작성 |
| 목표 | 자신만의 최적화된 AI 개발 환경을 빠르게 구축하고 반복 개선 |
| 기술 수준 | 중급~고급 개발자 |

### Secondary: 팀 리드

| 속성 | 설명 |
|------|------|
| 프로필 | 팀의 AI 개발 표준을 정립하려는 리드 엔지니어 |
| Pain Point | 팀원마다 AI 활용법이 달라 품질 편차가 큼 |
| 목표 | 팀 표준 워크플로우/에이전트를 정의하고 공유 |

### Tertiary: 커뮤니티 기여자

| 속성 | 설명 |
|------|------|
| 프로필 | 자신의 하네스 설정을 공유하고 싶은 개발자 |
| Pain Point | 좋은 설정을 만들어도 공유할 표준이 없음 |
| 목표 | 템플릿 마켓플레이스에서 공유/수익화 |

## 4. 기능 요구사항

### Must-Have (v1.0)

- [ ] 프로젝트 생성/열기 (기술 스택 프리셋 선택)
- [ ] CLAUDE.md 비주얼 에디터 (섹션별 편집, 프리뷰)
- [ ] 에이전트 CRUD (GUI 폼 → .claude/agents/*.md 자동 생성)
- [ ] 커맨드 CRUD (GUI 폼 → .claude/commands/*.md 자동 생성)
- [ ] 스킬 CRUD (GUI 폼 → .claude/skills/*/SKILL.md 자동 생성)
- [ ] Hook 설정 GUI (settings.json의 hooks 섹션 비주얼 편집)
- [ ] MCP 서버 관리 (목록, 설치, 제거, 상태 확인)
- [ ] 워크플로우 파이프라인 시각화 (단계별 상태, 실행)
- [ ] 기획문서 import (마크다운, PDF 드래그&드롭)
- [ ] 내장 터미널 (Claude Code CLI 실행)
- [ ] 에이전트팀 기획 기능 (서비스 기획 → PRD → 스펙 → 태스크 자동 생성)
- [ ] 기획 허브 (PRD, 스펙, 태스크 관리 및 traceability)
- [ ] 실시간 에이전트 모니터링 (실행 상태, 로그)
- [ ] lessons-learned 대시보드 (교훈 목록, 반복 패턴 감지)
- [ ] 자기개선 루프 GUI (자동 제안 → 승인/거부 → CLAUDE.md 갱신)

### Should-Have (v1.1)

- [ ] 워크플로우 드래그&드롭 커스터마이징
- [ ] 에이전트 노드 그래프 에디터
- [ ] MCP 서버 위저드 (GUI로 MCP 서버 생성)
- [ ] 워크플로우 실행 이력/타임라인
- [ ] 크로스 프로젝트 지식 전이
- [ ] Hook 실행 결과 실시간 모니터링
- [ ] 구조화된 터미널 출력 파싱

### Nice-to-Have (v2.0+)

- [ ] 커뮤니티 템플릿 마켓플레이스
- [ ] MCP 서버 플레이그라운드
- [ ] 품질 메트릭 대시보드 (시계열)
- [ ] 팀 설정 공유/동기화
- [ ] Figma/Notion 직접 연동

## 5. 비기능 요구사항

| 항목 | 요구사항 |
|------|---------|
| 성능 | 앱 시작 3초 이내. 프로젝트 열기 2초 이내. UI 반응 100ms 이내 |
| 메모리 | 유휴 시 200MB 이하 (Electron 기준) |
| 오프라인 | Claude API 없이도 설정 편집/관리 가능. 실행만 온라인 필요 |
| 보안 | API 키는 OS 키체인 저장. 프로젝트 설정은 로컬 파일 기반 |
| 확장성 | 플러그인 시스템으로 커뮤니티 확장 가능 |
| 접근성 | 다크/라이트 테마, 키보드 네비게이션 |
| 국제화 | 한국어/영어 기본 지원 |
| 플랫폼 | macOS 우선, Windows/Linux 후속 지원 |

## 6. 엣지 케이스

| 시나리오 | 예상 동작 |
|---------|---------|
| CLAUDE.md가 없는 프로젝트를 열 때 | 기술 스택 선택 위저드 자동 표시 |
| 이미 .claude/ 설정이 있는 프로젝트 | 기존 설정을 파싱해서 GUI에 로드 |
| Claude Code CLI가 설치되지 않았을 때 | 설치 가이드 표시, 설정 편집만 가능 |
| 대규모 CLAUDE.md (1000줄+) | 섹션별 lazy loading, 성능 최적화 |
| MCP 서버가 충돌했을 때 | 상태 표시 + 재시작 버튼 |
| 워크플로우 중간에 앱 종료 | 상태 저장 + 재시작 시 이어서 실행 옵션 |
| 동일 프로젝트를 여러 인스턴스에서 열 때 | lock 파일로 감지, 읽기전용 모드 제안 |
| 에이전트 .md 파일이 외부에서 수정되었을 때 | 파일 워처로 감지, GUI 자동 리프레시 |

## 8. 시스템 영향

### 기존 시스템과의 관계

| 시스템 | 관계 |
|--------|------|
| Claude Code CLI | 핵심 의존. CLI를 child process로 실행 |
| .claude/ 디렉토리 | 양방향 동기화. GUI 수정 → 파일 반영, 외부 수정 → GUI 반영 |
| CLAUDE.md | 파싱/렌더링/편집의 중심 |
| MCP 서버 | 기존 MCP 프로토콜 준수. 추가 관리 레이어 |
| Git | 워크플로우에서 브랜치/커밋 통합 |

### 생성하는 새로운 것들

| 항목 | 설명 |
|------|------|
| .forge-studio/ | 앱 전용 설정 (워크플로우 정의, UI 상태, 프로젝트 메타) |
| forge-studio.config.json | 글로벌 앱 설정 (테마, 언어, 기본값) |
| templates/ | 기술 스택별 프리셋 (CLAUDE.md, agents, commands 번들) |
